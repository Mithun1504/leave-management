# Leave Management Tasks

1. **Persist leave requests:** Extend database initialization with the `leave_requests` table, foreign key, status/type constraints, and lookup indexes; add schema and persistence tests for required fields and initial `Pending` status. **Acceptance criteria:** AC1.
2. **Calculate balances:** Implement yearly allocations, inclusive weekday counting, calendar-year splitting, and remaining-balance calculation from approved requests; test all leave types, weekends, holidays, year boundaries, midyear hires, and pending/rejected requests. **Acceptance criteria:** AC2, AC4, AC7.
3. **Create requests:** Implement employee-only `POST /api/leave/requests` with spec validation and transactional overlap checks; test valid creation, invalid inputs, overlaps, and no balance reservation. **Acceptance criteria:** AC1, AC7.
4. **Employee request and balance views:** Implement employee-scoped `GET /api/leave/requests` and `GET /api/leave/balances`; test response contents, current year, and exclusion of other employees' data. **Acceptance criteria:** AC5, AC7.
5. **Manager team view:** Implement manager-scoped request listing using current employee-manager assignments; test team inclusion, exclusion of other teams, and denial for admins or unrelated employees. **Acceptance criteria:** AC6, AC8.
6. **Manager decisions:** Implement `POST /api/leave/requests/{requestId}/decision` for pending requests, current assigned managers, final outcomes, and sufficient-balance approval; test approval deductions, rejection without balance effects, insufficient balance, wrong manager, and repeated decisions. **Acceptance criteria:** AC3, AC4, AC7, AC8.
7. **Verify concurrent operations:** Add transactional tests for overlapping concurrent submissions and concurrent approvals against one employee's balance; confirm no duplicate overlap, double decision, or balance overdraw. **Acceptance criteria:** AC1, AC3, AC4, AC7.
